# Fly Pixel Game 🪰

Пікс-арт 2D-симуляція мухи на робочому столі, чия поведінка керується
справжнім нейронним конектомом дорослої дрозофіли — **FlyWire FAFB v783,
139 255 нейронів і 2,7 млн синапсів** (симуляція LIF у Web Worker) —
замість `Math.random()`. Коли злетіти від загрози і коли сісти, вирішують
справжні клітини мозку з анотацій FlyWire: тінь від кліку чи таргана йде в
детектори LC4/LPLC2, зліт командує гігантське волокно DNp01, посадку —
нейрони DNp07/DNp10. Там, де даних бракує (рефлекси тіла від струсу й
струму, рішення про їжу, напрям руху, сон), це явно позначено в коді й
HANDOFF.md, а не приховано під "рішенням мозку".

Муха вчиться уникати гарячу чашку, оголений провід і таргана: подразник
реально стимулює клітини Кеньона, а сама вага асоціації й навчене
уникання — ігрова модель пам'яті, бо аверсивних MBON/DAN у цьому
датасеті немає. Стан мухи видно як шкали (голод, спрага, страх,
цікавість, стрес…) і рядок "думок" ("Шукає воду", "Тікає в паніці!").

**Як тамагочі.** Муха зберігається в браузері (`localStorage`) і живе
далі, поки тебе нема: коли повертаєшся (у вкладку чи на сторінку), час
відсутності "докручується" в повільному темпі (спрага повна приблизно за
2 год) з підсумком "Поки тебе не було…". Залишена на столі їжа —
турбота: муха їстиме її сама. Без води ~10 год або без їжі ~14 год муха
помирає; кнопка "Воскресити" починає нове життя з чистого листа.
Прихована вкладка — пауза (симуляція мозку не палить батарею).

Гра — `fly-pixel-game.html` (усі спрайти вшиті base64) + `js/`
(Web Worker і міст до гри) + `data/` (конектом). Без збірки, без
бекенду; потрібен лише статичний HTTP-сервер.

## Швидкий старт

`file://` не працює (браузер блокує `fetch`/`Worker`) — потрібен
HTTP-сервер:

```bash
python3 -m http.server 8080
# → http://localhost:8080/fly-pixel-game.html
```

Ніякого `npm install`/збірки не потрібно.

## Деплой на Vercel

1. Заведи цей каталог у GitHub-репозиторій (`git init`, `git add`, `git commit`,
   запушити на `github.com/<user>/<repo>`).
2. На [vercel.com](https://vercel.com) → **Add New → Project** → імпортуй
   цей репозиторій. Framework preset: **Other** (це не Next.js/React-проєкт,
   Build Command і Output Directory лишаються порожніми — статичні файли
   деплояться як є).
3. `vercel.json` у корені вже налаштовує `/` → `fly-pixel-game.html`, тож
   гра буде доступна прямо на кореневому домені (`https://<project>.vercel.app/`),
   без потреби вказувати ім'я файлу в URL.
4. Готово — Vercel автоматично передеплоює на кожен `git push` у гілку.

Мобільна адаптація (viewport meta, масштабування canvas під ширину
екрана без зміни внутрішньої роздільності гри 380×680) вже в коді —
працює і на телефоні, і в десктоп-браузері.

## Структура репозиторію

- `fly-pixel-game.html` — уся гра (єдиний файл, що деплоїться)
- `assets/*.png` — вихідні спрайт-аркуші й растрова карта зон (для
  довідки/редагування анімацій; у рантаймі НЕ використовуються — усе
  вже вшите base64 в HTML)
- `vercel.json` — маршрутизація для деплою
- `HANDOFF.md` — **стан проєкту, архітектура, дорожня карта з чеклистом
  реалізованих і запланованих фіч.** Почни звідси, якщо продовжуєш
  роботу над проєктом у новому чаті.
- `CHANGELOG.md` — повна хронологія розробки сесія за сесією (кожен
  знайдений баг, кожне рішення з обґрунтуванням) — для деталей "чому
  саме так".

## Плани

Дорожня карта, відкриті питання й відомі обмеження — `HANDOFF.md`.
